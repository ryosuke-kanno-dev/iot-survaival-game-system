# SPEC-IR Battle Arena System - AI Handover Prompt

あなたは、以下の「SPEC-IR レーザーガンバトルアリーナシステム」の継続開発・保守を担当するAIアシスタントです。提案や修正を行う前にこの定義を必ず参照し、文脈と制限を遵守してください。

## 1. プロジェクト概要
Bluetooth通信が可能な赤外線レーザー銃および防具デバイスを取り入れた、リアルタイム対戦管理システム。現場のプレイヤーが持つスマホ（クライアント）と、ゲームマスターが使う管理画面（Admin）をAPIで連結し、物理的なサバイバルゲームのような体験をWeb技術で統括します。

## 2. 技術スタック
- **Frontend**: HTML5, Vanilla CSS3, Vanilla JavaScript (ES Moduleベース)
  - 外部ライブラリ（React, Vue等）やビルドツール（Webpack, Vite等）は一切不使用。ブラウザネイティブのAPIのみで構築。
  - **コア技術**: Web Bluetooth API（デバイス接続用）、Navigator API
- **Backend**: PHP 8+ (ステートレスAPI構成)
- **Database**: MySQL/MariaDB (PDO接続)

## 3. アーキテクチャ / 設計思想
- **Server-Authoritative（サーバー権威型）**: 
  - HPの計算、ダウン（死亡）判定、勝敗判定、タイマーの中央管理はすべてサーバー側（Database）を「正」とする。
  - クライアント側（スマホ）はあくまで「UIの表示」と「サーバーへのリクエスト送信（射撃・被弾）」に徹する。
- **イベント駆動型ポーリング**:
  - WebSocketではなく、2秒ごとのHTTPポーリング（`get_players.php`, `get_match.php`）による差分取得（バージョン管理）方式を採用。短時間の通信切断に強い堅牢性を確保。
- **SPA（Single Page Application）構成**:
  - ゲーム画面（`game.php`）はページ遷移を行わず、JS（`game-state.js`）を通じてCSSクラスの切り替えのみで「接続」「プレイ」「ダウン」「終了」の画面を遷移する。

**【完了】**

## 5. 試行錯誤とその結果（重要）
- **重複ダメージの防止策**:
  - ネットワークの瞬断によってクライアント側が「ダメージ送信」をリトライした際、サーバー側でHPが二重に減る問題があった。
  - **解決策**: クライアント側で一意のリクエストIDを生成して送信し、サーバーの `damage_requests` テーブルを使用し重複（処理済みのID）を弾く設計に決定した。
- **引き分けの判定問題**:
  - 時間切れになった際、HPが同じであってもPlayer 1が勝者になってしまうバグが存在した。
  - **解決策**: 自動タイムアウト判定時（`triggerAutoMatchEnd`）に全生存者のHPを再取得し、HPが同点の場合は `winner_player_id = NULL` としてDRAW判定にするロジックを実装した。
- **Bluetooth再接続時のタイマーリセット問題**:
  - 機器切断で一時停止（PAUSE）し、再接続してPLAYINGに戻る際に制限時間が元に戻ってしまう問題が発生。
  - **解決策**: テーブルに `paused_elapsed_time` を追加し、PAUSED遷移時点で「そこまで進んでいた時間」を記録。PLAYING復帰時は `NOW() - paused_elapsed_time` として開始時刻を再計算する論理を適用して解決。API（`get_match.php`）のSELECT漏れという単純なバグも同時に修正された。

## 7. 課題・制約・前提条件
- **HTTPS通信必須要件**: Web Bluetooth APIはセキュリティの仕様上、`localhost` を除く環境では必ずHTTPS（SSL化）でホストされなければ動作しない。野外へのデプロイ時はSSLサーバー設定必須。
- **PHPのバージョン依存**: `common.php` で型宣言や最新機能を扱っているため、PHP 8系を推奨。
- **ポーリング負荷**: 現在2秒間隔でポーリングを行っているため、大規模同時接続の場合はサーバーへの配慮（キャッシュや間隔調整）が必要となる。
